## Цель и результат

Написан клиент, который получает задачи и категории у готового учебного сервера.
Клиент проверяет ответы, различает ошибки, ограничивает время ожидания и поддерживает отмену запроса.
Пользовательского интерфейса в этой работе нет.

## Запуск

Из корня проекта перейти в папку работы:

```bash
cd practice-05
```

В первом терминале запустить сервер:

```bash
npm start
```

Во втором терминале, тоже в practice-05:

```bash
npm run client
npm run example:fetch
npm run example:order
```

API: http://127.0.0.1:5505/api. Остановка сервера — Ctrl+C.
При другом порте: `node api/server.mjs 5515`, затем во втором терминале
`API_URL="http://127.0.0.1:5515/api" npm run client` (macOS/Linux).

Проверки запускают необходимые серверы сами:

```bash
npm test
npm run check:own
npm run example:measure
```

`npm test` последовательно проверяет сервер, клиент без сети и клиент с настоящим сервером.
`check:own` запускает дополнительные случаи, `example:measure` сравнивает время запросов.

## Порядок выполнения

Прогнозы были записаны до запусков.

| Эксперимент | Ожидание | Фактический порядок |
|---|---|---|
| Исходный файл | A B C D E F | A B C D E F |
| Добавлен Promise в конце файла | A B C D E G F | A B C D E G F |

A, B и C выполняются сразу. После них идут D, E и добавленный G — обработчики Promise и продолжение после await.
Таймер F выполняется после них. Задержка 0 не означает немедленный запуск.
Если удалить один обработчик Promise, его метка пропадёт, порядок остальных здесь сохранится.

## Файлы и логика

| Файл | Назначение |
|---|---|
| api/server.mjs | Готовый сервер преподавателя |
| src/api-client.js | Адреса, fetch, JSON, ошибки и отмена |
| src/task-api.js | Запросы задач и категорий, проверка их полей |
| src/variant.js | Номер и фильтр варианта |
| src/main.js | Общий сценарий и вывод в терминал |
| examples/measure.js | Три сравнения времени запросов |

Адрес собирается через URL, параметры — через URLSearchParams. Пропускаются undefined, null и пустая строка,
но сохраняются false и 0. Запрос передаёт Accept: application/json.
Сначала проверяется response.ok. При успешном 204 возвращается null. В остальных успешных ответах проверяется
Content-Type, затем разбирается JSON. fetchFn передаётся параметром, чтобы в проверках заменить сеть подготовленным ответом.

В task-api проверяются поля каждой задачи и категории, уникальность id и равенство meta.total длине списка.
Задача содержит положительные целые id и categoryId, непустое название до 100 символов,
логический completed и приоритет low, medium или high. JSON может быть правильным текстом, но содержать неверные поля.

loadInitialData возвращает tasks, categories и meta. Запросы задач и категорий начинаются вместе через Promise.all.
HTTP-клиент не знает устройство задачи, поэтому проверки её полей находятся отдельно.

## Ошибки

| Случай | Ожидаемый kind | Фактический результат |
|---|---|---|
| Задача 999 | http | http, 404, TASK_NOT_FOUND, details: {id: 999} |
| completed=yes | http | http, 400, INVALID_QUERY |
| /debug/error | http | http, 503, SERVICE_UNAVAILABLE |
| /debug/invalid-json | invalid-response | invalid-response |
| /debug/text | invalid-response | invalid-response |
| API остановлен | network | network |
| Задержка 150 мс, тайм-аут 20 мс | timeout | timeout |
| controller.abort() | aborted | aborted |

Тайм-аут создаётся через AbortSignal.timeout. Внешняя отмена объединяется с ним через AbortSignal.any.
При HTTP-ошибке сохраняется статус даже тогда, когда тело ответа не является JSON.
После остановки сервера запуск клиента дал network. После повторного запуска снова получены id 4, 13, 34 и три категории.

## Отладка и вывод

Для просмотра в VS Code удобно ставить точки останова перед fetch, после Response, перед response.json и в catch.
Фактически проверены ответы 200 и 404 через запросы и проверки; сессия отладчика с точками останова отдельно не проводилась.
При 200 response.ok = true и возвращается data. При 404 response.ok = false, payload содержит error,
а клиент создаёт ApiError с kind=http, status=404 и code=TASK_NOT_FOUND.

Дополнительные задания (allSettled и повтор запросов) не выполнялись.
Основной результат — работающий модуль чтения API. Promise представляет будущий результат, await ожидает его.
Ответ с ошибочным статусом отличается от отсутствия соединения, поэтому эти случаи обрабатываются отдельно.
